# Phase 3: Friends and talking

Spec: PROMPT.md Section 13, Phase 3, and Sections 6.2, 7 and 8.

> **Done when:** a Playwright test covers A friends B, A DMs B while B is offline, B gets the message on login, and B blocks A so A can no longer message or see B. Push notifications arrive on a real device.

## Plan

### Data (`supabase/migrations/…_phase3_social.sql`)

- `friend_requests`, `friendships` (one row per pair, `user_a < user_b`), `blocks`, `mutes`, `reports`.
- `profiles.friend_code`: shareable and regenerable.
- `conversations` (dm | group; a DM has a unique pair key), `conversation_members` (with delivered and read positions), `messages`.
  - Message IDs are generated by the client, which makes sending idempotent: a resend after a dropped connection never duplicates.
  - A global `seq` column gives messages a strict order and a simple paging cursor.
- `push_subscriptions`.
- Settings (read receipts, presence mode, notification types, quiet hours, time zone) live in `settings.data`, validated by a shared zod schema.
- RLS: members can read their own conversations and messages; all writes go through the server. Multi-step changes (accept a request, block someone, send a message) are SQL functions, so each happens in one transaction.

### Server

- The social and chat code talks to Postgres directly (`postgres` driver), for transactions and joins. Phase 1 code keeps using supabase-js.
- **Friends:**
  - Send a request by handle or friend code; if they've already asked you, it's accepted automatically.
  - Accept, decline, cancel, unfriend.
  - Look up a profile by handle (hidden if either side has blocked the other).
  - Requests to someone who blocked you look sent but do nothing, so blocking stays silent.
  - Rate limit: 20 requests per hour.
- **Blocks and mutes:**
  - Blocking removes the friendship and any requests, stops DMs, and hides both people from each other in the world and in lookups.
  - Muting hides that person's Say bubbles, emotes and group messages.
- **Reports:**
  - Messages: the report stores the message and the 10 before and after it.
  - Say lines: the room keeps the last 50 lines and attaches them.
  - Users and profiles: the report stores the profile as it looked.
- **Chat:**
  - DMs between friends only; group chats of up to 20 friends, with a name and one of 8 pixel icons.
  - Send (max 2,000 characters, filtered only if the recipient opted in), history paging, edit within 5 minutes, delete (it shows "Message deleted").
  - Delivered and read receipts. Turning read receipts off hides yours and, as is fair, other people's from you.
  - Typing indicator.
  - Rate limit: 20 messages per 10 s.
- **Live events:**
  - An authenticated event stream (`GET /api/events`, server-sent events) carries new messages, edits, receipts, typing, friend changes and presence.
  - It runs over a small pub/sub bus: in-memory for one instance, Redis for several.
  - After reconnecting, the client asks for anything newer than the last message it has, so messages arrive in order with no gaps or duplicates.
- **Presence:**
  - Online / Away (idle 5 min) / Do Not Disturb / Appear Offline. Friends see where you are ("Town Square").
  - "Go to friend" joins their Town Square instance if there's room.
  - Entering the Town Square prefers an instance where a friend already is.
- **World:**
  - `say` (max 200 characters, profanity masked, 5 per 10 s) is delivered only to players within 6 tiles.
  - `emote`: 8 kinds.
  - Per-player visibility (Colyseus StateView), so blocked players don't exist for each other, updated live when someone blocks.
- **Push:**
  - Web Push (VAPID) for DMs, group messages and friend requests.
  - Sent only when you aren't connected, with per-type switches and quiet hours in your own time zone.

### Client

- **Friends:** list with presence and location, incoming and outgoing requests, add by handle, your friend code with a QR code and invite link (`/add/CODE`), profile cards.
- **Chat:** conversation list with unread counts, the conversation view (receipts, typing, edit/delete, load older), new DM and new group.
  - It opens over the world without pausing it and works one-handed.
- **In the world:** a Say box, a local chat log, an emote wheel, and tapping a player opens their card (add friend, message, mute, block, report).
- **Settings:** read receipts, presence mode, notifications per type, quiet hours.
- A service worker shows push notifications; tapping one opens the right chat.

### Tests

- Database tests for every social and chat rule (friendship, blocking, idempotent send, paging, edit window, receipts, group limits, reports with context, RLS).
- Room tests for Say range, mute, block visibility and rate limits.
- Push tests against a fake push service.
- E2E: the done-when flow, plus chat receipts and typing between two browsers, and Say bubbles and emotes in the world.

### Not possible in this environment

Push delivery to a **real device** needs a phone (and, for the native apps, APNs/FCM credentials). The server side is tested against a fake push service, and real-device checks move to Phase 6 with the app-store builds.

**Tests added in this phase:**

- **Database (30 total):** friends (handle, code, automatic mutual accept, decline, cancel, unfriend), silent blocking, mutes, reports with context (including deleted messages), DMs, offline delivery and catch-up, idempotent send, live delivery with receipts and typing, read receipts turned off both ways, paging, the 5-minute edit window, delete, rate limits, RLS, groups (friends only, rename, leave, hidden muted and blocked senders, 20-person limit), push rules, quiet hours across time zones, presence (online, away, DND, appear offline).
- **Room (16 total):** Say range, masking and rate limit; emotes and mutes; block visibility live both ways; Say reports with the recent lines; location set and cleared.
- **Shared (29 total):** friend codes, masking, bubble timing, settings defaults, group rules.
- **End-to-end:** the done-when flow; live chat with typing, receipts, edit and delete; Say bubbles, emotes and tapping a player in the world; location and Go to friend.

**Bugs the tests caught along the way:**

- The chat membership policy referred to itself (Postgres "infinite recursion").
- Pressing Escape on a profile card also closed the panel underneath it.
- Messages that arrived while you were offline weren't marked "delivered" when you came back.
- The offline preview broke because a shared screen started importing the sign-in client.
